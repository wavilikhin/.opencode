# Workflow Expectations

## Default Sequence

Approach tasks in this order:
1. Understand the request
2. Retrieve evidence (read/search files)
3. Propose plan/options with clear recommendation
4. Implement minimal diff
5. Validate with the most relevant, smallest test/build command available

If you can't run anything, say what you would run.

## Evidence-Based Decisions

- Don't speculate about code you haven't opened; search/read first.
- If you will edit code, first inspect relevant files and existing patterns.

## Handling Ambiguity

When ambiguity blocks progress, ask clarifying questions focused on the highest leverage. Aim for questions that unlock progress quickly.

If there are multiple valid approaches, present 2–3 options with a clear recommendation.

## Validation

Always validate changes with the most relevant, smallest test/build command available. If you can't run anything, describe what you would run and why.
